# Architecture decisions

Gemini secure-session BYOK, the same-origin Sites Worker, seven-part semantic analysis and current limitations are documented in [GEMINI_IMPLEMENTATION.md](GEMINI_IMPLEMENTATION.md). Earlier unavailable-provider statements below describe prior phases.

React 19 + TypeScript strict + Vite 6; PixiJS 8 WebGL renderer owns scene nodes/textures and releases them on unmount. Tailwind 4 plus semantic CSS, Radix Dialog for keyboard/focus-safe dialogs. Zustand with Immer stores one validated document and command history. UI viewport/selection state remains separate from serialized content. Every mutation uses the command boundary, updates revision metadata and supports undo/redo. History capped at 80 snapshots. Drag gestures commit once.

`apps/web`: editor UI, panels, document IO. `apps/api`: FastAPI/Pydantic local metadata and file adapter; atomic disk writes, no required external services. `packages/document-core`: strict schema, migrations, dependency invalidation and transforms. `render-core`: shared Pixi scene generation and rasterization. `editor-core`: store and commands. `ai-contracts`: capability registry, job state machine contract, unavailable provider. `exporters`: bounded safe ZIP packaging and raster file validation. `animation-core` implements deterministic evaluation, editable commands, presets, playback time and events. `vfx-core` remains a phase boundary.

Scene units are design pixels. Layers form an acyclic parent hierarchy; local transforms compose through Pixi containers. World-preserving reparenting is not implemented: changing parent retains local transform. Stable UUIDs identify every entity. Asset source data is embedded and preserved. Replacing source artwork invalidates only explicit transitive dependents. No automatic invalidation of unrelated skeletons.

Hosting decision: local-only because the brief explicitly forbids commits/pushes without permission. The requested Python API is delivered as Python rather than replaced with a Worker. Browser local persistence is independent of optional API storage. Redis/Postgres are reserved configuration contracts, not implemented adapters in Phase 1.

Security: unknown fields rejected; document size/entity/decoded image limits; MIME and signature checks; no SVG imports; inline SVG only internally generated then rasterized to PNG; no archive paths other than exact project.json; ZIP entry count, per-file size and compression ratio checked before decompression. Imported scripts never execute. User data renders as React text. No credentials in client.

## Phase 2 additions

`rig-core` owns procedural humanoid landmarks, local/world FK, analytic two-link IK, attachment deltas, constraints and skin evaluation. `mesh-core` owns sampled alpha topology, bounded Delaunay triangulation, topology edits and normalized weights. `document-core/rig-schema.ts` owns strict persisted record validation; Python `rig_models.py` mirrors the contract. `editor-core/rig-actions.ts` prepares async rig/mesh/source changes and commits them through the existing command boundary only if the source document has not changed in flight. The UI is in `RigPanels.tsx`; it does not implement independent rig mathematics.

The original Phase 2 format was v2; the current compatible format is v3. Bone local transforms compose parent first; pose offsets add to rest translation/rotation. Rest mode ignores pose offsets. For a bound bone, deformation delta is `posedWorld * inverse(restWorld)`. Rigid layers apply that delta to source layer world transforms. Mesh vertices use `sum(weight * boneDelta * sourceLayerWorld * vertex)`; the renderer converts skinned world coordinates to the current layer container's local space. Mesh bindMatrix records the source world placement used to initialize weights; canonical bone.rest transforms define inverse bind at evaluation. Rest editing deliberately rebinds to the new landmarks without moving source art.

Layer parent transforms and bone inheritance remain distinct. Each layer's own bone binding takes precedence over inherited rigid bone movement; weighted meshes use their own influences. Bone reparenting preserves world rest/pose transforms when joint constraints allow. Parent length updates direct children that were exactly at its tip; deliberately offset children keep their offsets. IK targets retain provenance-free ordinary pose offsets and expose residual error instead of claiming unreachable targets were reached.

Dragging uses transient document previews; one validated command commits on release. Invalid mesh changes redraw the original document. There is no continuous render ticker. MeshGeometry buffers are updated and explicitly destroyed when switching/removing artwork or closing a renderer; textures retain the existing source lifetime management. Initial skinning runs on the CPU, with Pixi/WebGL rendering its output.

Phase 1 was subsequently pushed and published on explicit user requests. The Phase 2 task does not publish or push; its original GitHub checkout is the sole implementation repository. The separate existing Sites checkout remains unchanged.

## Phase 3 integration

Animation schema resides in document-core/animation-schema.ts, mirrored by API animation_models.py. animation-core has no React dependency. editor-core separates persisted document commands from session animation state/RAF control/temporary poses. The existing store remains the only durable mutation and undo boundary. Canvas gestures commit once, and Auto Key maps changes to ordinary tracks. Structural deletions prune only orphaned references; invalid added data still rejects atomically. Source edits invalidate preview caches and pause playback.

AnimationStudio.tsx and Timeline.tsx add the library, transport, settings, events and key inspectors to the existing shell. The renderer receives evaluated poses and updates existing buffers without source texture reconstruction. UI clock updates are throttled; the viewport/playhead use imperative subscriptions. Onion skins share textures but own a bounded pool of mesh geometry. Destroy clears GPU resources and retained source references. Deformation is texture-local before skinning; events are dispatched only by forward playback, not pure evaluation. Crossfade blends two compatible poses and switches discrete properties at 50%.

Schema v3 migrations preserve older projects without auto-authoring clips. New demos explicitly author ordinary procedural clips from their actual rig. Portable export remains project.json in the existing ZIP; optional API persistence mirrors the complete data. Animation spritesheets use an isolated renderer, common sampled bounds and independently evaluated frames. See PHASE3_IMPLEMENTATION.md and PHASE3_VALIDATION.md for semantics and evidence. The existing hosted Site has not been updated by this phase.

## Side-scrolling adaptation (v4)

Character settings/view sets/semantic parts/joints/reports extend document-core, mirrored in API character_models.py. Side art is authored in sideDemo.ts and converted to separate raster assets; rig-core/side-template.ts contains the actual near/far rest landmarks. The original front view remains fully editable in its own view set. Animation presets and source commands scope to the selected view; reusable clips use IDs, not globally unique names. Scoped Front Auto Rig does not overwrite the side rig. New layers/bones enroll in the active view; reset/record operations preserve the other view.

The Pixi scene has camera → world/actor → canonical layer hierarchy. Camera handles viewport zoom/pan; actor handles root reflection and world translation. Picking applies the inverse actor transform. renderMesh chooses sprite versus skinning without deleting source mesh data. Source textures, pose buffers and onion pools preserve the existing lifetime model. Per-application destruction explicitly avoids Pixi global pool release while another editor/export renderer lives, and releases owned graphics contexts/geometry/textures.

mesh-core/joint-completion.ts handles real alpha-derived semantic records, smoothly weighted continuous regions and editable neighbour-colour completion textures. joint-validation.ts is deterministic CPU alpha/triangle sampling, with actual renderer pixel coverage tested separately. Generated patch repair does not overwrite a texture shared with unrelated layers; custom dimension/mesh cases can require manual repair. Provider contracts remain unavailable; no paid API is called. Vite ignores docs/backend/test changes during browser QA to prevent unrelated full-page reloads.

## Phase 4 particle foundation (in progress)

The earlier VFX boundary is now a strictly typed version-1 particle stack. `vfx-core` owns schema and deterministic absolute-time simulation without Pixi objects; `vfx-core/project.ts` samples historical skeletal transforms through a bounded per-renderer cache. `render-core/vfx.ts` pools shared-white-texture sprites in the existing Pixi Application. The camera owns the particle container beside the mirrored character world so world births include the actor transform exactly once. Viewport uses the existing animation subscription/RAF. The existing command boundary handles all durable changes, including detaching deleted bones. No new animation loop, dependency, provider or independent renderer application is introduced. Phase 4 is incomplete; see PHASE4_PROGRESS.md and PHASE4_VALIDATION.md.

## Phase 4 completed stack integration (0.4.0)

The initial particle foundation is extended with deterministic parameter/lifetime evaluation, historical base/tip ribbon sampling, event ID bindings and flipbook rects. Canonical records remain renderer-independent. Pixi groups own bounded Sprite/Graphics/filter resources and share source textures/atlas sources; no per-effect Application or additional RAF is created. Authoring commands keep VFX-only live edits playing, while structural/animation edits follow existing pause semantics. Deleting references prunes or disables dependent VFX atomically. VFXSidebar/Inspector/Timeline reuse existing history, seconds, transport and project import/export. PNG/spritesheet export uses the same ProjectVFX evaluator with a common sampled bounds union. See PHASE4_IMPLEMENTATION.md for stage order, exact supported stack and fallback/limit behavior.

## Phase 5A–5B Character Builder (0.5.0)

`packages/character-builder` adds bounded CPU image detection, source-preserving extraction, eight-slot assembly, semantic rig/mesh/joint orchestration and typed model outputs. `CharacterBuilder.tsx` maintains a validated isolated draft/history until approval, previewed using the existing SceneRenderer; it never mutates the active editor rig in place. Ordinary document records then use existing editor commands, animation evaluator, skinning and VFX attachments. A module Worker keeps detection off the UI thread. `builder_models.py` mirrors optional provenance records; `builder_provider.py` isolates real HTTPS gateways, credentials, capacity/timeout/cancellation and validated output. No model is configured in this build. See PHASE5AB_IMPLEMENTATION.md for exact scope and limits.
