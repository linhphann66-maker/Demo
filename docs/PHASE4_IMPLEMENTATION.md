# Phase 4 — editable 2D VFX Studio (0.4.0)

This continues the existing editor and side-scrolling Flame Knight. Original artwork, rig, skinning, animation tracks, history and project ZIP are preserved. This is a procedural VFX engine/editor; no paid or fabricated AI generation is included.

## Try it

1. Open **VFX** in the left navigation. Choose **Sword Fire**, **Fire Slash**, **Impact Burst**, **Magic Aura** or **Footstep Dust**. The effect is an editable instance. Fire Slash/Impact bind to real Attack events; Footstep Dust detects foot contacts on the actual Walk/Run trajectories and creates editable events/instances.
2. Select the preview animation and Play. The same Phase 3 clock, seconds, FPS and RAF controller drive bones, meshes and effects. Pause freezes the pose/effect. **Dừng preview VFX** pauses and clears the transient VFX preview; **Phát cùng hoạt ảnh** resumes; **Về đầu** restarts. Source visibility is separate and affects exports.
3. Change intensity, colors or emitter parameters. VFX-only edits keep playback running; structural imports and animation edits pause normally. Local particles follow the current attachment; World particles retain their birth transform while the animated attachment moves.
4. Enable gizmos. Drag an emitter center, weapon base/tip or flipbook attachment on the canvas. One gesture commits one undoable attachment-offset edit. Inspector fields allow precise offsets, pinned positions, rotation/scale inheritance and bone selection.
5. Pick a target/property, move the shared playhead, set a value and add a key. Linear/stepped/Bezier interpolation, easing handles, color interpolation, moving/deleting keys and copy/paste work. The VFX timeline displays parameter keys and real animation events; Inspector has exact numeric editing. Keys use seconds local to the effect, while events and the shared ruler use clip seconds. Looping keys repeat with the effect cycle.
6. Save normally or export `.a2dstudio`. Effects, presets, triggers, keys, curves, markers, textures and flipbook metadata stay editable. Export/import effect JSON with embedded referenced textures for reuse. Missing rig/event references on another character are explicitly rebound/detached and reported, then editable in Inspector.
7. Export a transparent VFX-only spritesheet or character+VFX spritesheet. Configure FPS, duration, width and height. ZIP contains an actual rendered PNG atlas and frame/event metadata. The regular PNG export includes the current preview's VFX. Export uses the selected quality and excludes gizmos/onion skins.

## Architecture and data

`vfx-core/schema.ts` and `extended-schema.ts` contain strict version-1 stack schemas; `parameters.ts`, `scene.ts`, `project.ts`, `presets.ts`, `footsteps.ts`, `validation.ts` implement pure evaluation. Canonical data contains no Pixi runtime objects. `render-core/vfx.ts` adapts evaluated particles/ribbons/flipbook frames to the existing Pixi Application. `editor-core/vfx-actions.ts` and the existing command boundary handle gestures/deletions/history. Session quality, clipboard, selection, preview-stop and warnings are not serialized.

This is the permitted **structured effect stack**, not an arbitrary node graph. Existing `nodes` contain ParticleEmitter/SpriteEmitter records; typed `trails`, `flipbooks`, `filters`, `tracks` and `trigger` complete the stack. EffectGroup corresponds to the effect's render group; EventTrigger/Delay are its validated trigger fields. Connections which have no semantics are not accepted. There is no decorative graph editor.

The document remains v4 with a versioned VFX extension. Old empty arrays and the earlier particle-only version-1 records remain loadable unchanged; new fields and `vfxPresets` are optional. IDs across effects, components, keys and lifetime curves are globally unique. Imports reject unknown fields, unsupported types, invalid/missing references, bad frame bounds, duplicate tracks/timestamps, nonfinite/out-of-range data and excessive resources. Python mirrors this contract. Earlier application builds cannot read the extended records and should not resave them.

Per emitter: position/direction, continuous rate/burst, max particles, lifetime and variation, velocity/variation, acceleration, gravity, drag, scale/variation/end scale, rotation/angular velocity, color/opacity, six spawn shapes, texture/blending, Local/World attachment and optional orbital motion. Scale/opacity/color lifetime curves use normalized 0–1 time and stable editable keys. Gravity is in the selected simulation coordinates; acceleration starts in emitter coordinates. Orbital motion is a deterministic procedural position modifier rather than a rigid-body physics solver.

Parameter channels: rate, speed, effect intensity, color, opacity, scale, rotation, filter strength/glow, trail width and emitter/filter position. Channels are checked against the target type. Numeric ranges are validated and defensively clamped at evaluation. Editing duration proportionally retimes parameter keys, not animation events. Effect presets are independent definitions with detached bones/event bindings; using one creates fresh IDs and records. Editing an instance never mutates its preset or another instance.

## Evaluation and event semantics

1. Resolve clip/view and start/stop event IDs (including delay). Event time edits immediately change evaluation; a disabled/missing start suppresses the effect, a disabled stop uses duration. Reference deletion disables dependent effects and clears the broken binding atomically; undo restores it. Trigger editing never dispatches duplicate external animation events.
2. Convert clip seconds to local effect seconds. Unbound looping effects restart their emission/random history at cycle boundaries. Event-bound effects are one-shot relative to their start; burst mode emits only at start. Seeking reconstructs state directly and is silent to Phase 3's external event dispatcher. Forward frame skips, restarts and loop boundaries produce the same state as evaluating that exact time. A clip loop restarts its VFX history; carry-over particles across cycle boundaries are intentionally not accumulated.
3. Particle birth rate is integrated on a 120 Hz fixed grid, including animated rate/intensity. Seeded randomness is reproducible. Capacity rejects births at emission time; rejected particles are never resurrected. Closed-form acceleration/drag integration includes fractional final time without accumulated frame deltas. Particle parameters sample at birth; lifetime curves sample normalized age. World particles use historical bone/actor matrices, Local particles the current attachment matrix. Mirroring does not modify source bones, UVs or keys.
4. A trail samples **both actual base and tip matrices** on a fixed grid, caps segments and reconstructs the ribbon from its recent lifetime. Width, color gradient, opacity/fade curve, taper, smoothing, texture and blend are editable. Sampling stops at the bound stop event; existing rows fade out. There is no persistent ghost geometry or orientation guessed from a static world point.
5. Flipbooks select source-rect descriptors from FPS, offset and loop; source images and raw imported metadata are retained. Multiple emitters, trails and flipbooks can coexist in one effect and use its trigger.
6. Each effect renders in document order. The fixed modifier stages apply transform/tint/opacity, additive soft glow and scoped distortion/dissolve. One filter of each type avoids ambiguous duplicate modifiers. These are real fixed GLSL filters and blur/additive render paths, not arbitrary imported shader execution. Dissolve/distortion affect the combined VFX group, including glow. Low quality reduces particles and disables expensive filters; changing quality never changes authoring data.

During animation crossfade, destination-clip effects/event bindings own emission history. Local attachments use the current mixed pose; historical trails/world births use destination-clip sampling. Source-clip VFX are not separately crossfaded. This is deterministic destination ownership, matching Phase 3 event ownership, not a VFX transition mixer.

World X/facing edits in the editor relocate/re-evaluate an authored simulation. An external game actor with independent runtime world motion must supply historical transforms through the engine sampler; this editor does not invent a game-world movement track or an engine-specific runtime.

## Rendering, limits and cleanup

Simple particles use Pixi's shared-texture GPU Sprite batch path. ParticleContainer was considered; heterogeneous textures/blends and scoped grouping/filters make pooled Sprites a simpler compatible adapter here. Simulation and skinning remain CPU-side; GPU compute is not claimed. A lazily generated soft radial texture is owned by each renderer, while imported textures/atlas sources are reused. Flipbooks cache rect descriptors rather than rebuilding GPU source textures each frame. Ribbons rebuild bounded Graphics geometry; each trail has its own blend path. Group hide/delete removes owned GPU resources; teardown destroys filters, contexts, rect descriptors and owned texture sources without releasing Pixi global pools used by another editor/export renderer.

Limits: 32 instances, 64 saved presets, 8 emitters/effect, 1024 particles/emitter, 2048/effect budget, 4096 visible particles globally, 8 trails and 8 flipbooks/effect, 256 samples/trail, 512 frames/flipbook, 128 parameter tracks/effect, 2048 keys/track and 20000 parameter keys/project. Sprite pools retain bounded high-water resources (8704 across visible/halo/flipbook pools); inactive excess is reclaimed. Matrix cache max512, frame-rect cache max1024. Existing image/project/ZIP limits still apply. Export evaluates a common sampled bounds union with effect/filter padding so animated poses/effects fit one consistent frame transform; it does not accumulate all frame particle objects in memory.

The app uses one existing animation RAF loop and pauses on hidden documents. WebGL context loss pauses preview and reports a recovery/reload message; actual restoration is delegated to Pixi's context system. Shader/render errors disable scoped filters and report an explicit fallback rather than showing a fake successful effect.

## Supported scope and limits

- Supported: procedural particles, textured sprite particles, motion ribbons, flipbooks, soft additive glow, tint/alpha, transforms, basic sinusoidal UV distortion and threshold noise dissolve; editable keys, events, presets, local/world attachments, mirroring, portable data and PNG spritesheets.
- No full free-form visual graph editor; the typed stack is the functional alternative allowed by the brief.
- Atlas frames must be unrotated and untrimmed rectangles. Rotated/trimmed packing is rejected explicitly. This does not flatten source frames into a particle definition.
- No GIF/MP4, arbitrary user-authored shaders, HDR threshold bloom or Unity/Godot/Phaser importer/runtime is claimed. JSON is application-specific editable data. No Phase 5 AI generation/provider has been integrated; SDK contracts and an unavailable-provider implementation are present.
- The inherited non-loop spritesheet convention includes a final zero-duration endpoint. Large/extreme/custom configurations may require Low quality, lower budgets or manual marker/curve/art adjustment.
- Tests use Chromium/software WebGL. Performance is measured CPU plus render submission time, not guaranteed GPU FPS. No Safari/Firefox/mobile/long-duration/native-GPU/context-loss-injection coverage is claimed.
